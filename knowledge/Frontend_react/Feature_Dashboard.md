# Feature: Live Dashboard (главный экран)

> **Назначение документа:** описание главного экрана DeskHub — крупные часы, раскладка виджетов в сетке 1024×600, анимации появления и поведение экрана в режиме 24/7.
> Каркас (стор, UI-кит, SignalR) — в [`Core.md`](Core.md). Виджеты — в [`Feature_Widgets.md`](Feature_Widgets.md).

---

## 1. Назначение

Live Dashboard — экран по умолчанию, который видно **99% времени**. Он должен:

1. Мгновенно отвечать на вопросы «Который час?», «Что на улице?», «Сколько ехать на работу?».
2. Не требовать взаимодействия — всё видно без тапов.
3. Работать неделями без деградации производительности и без выгорания экрана.

Расположение: `src/features/dashboard/` (экран и сетка) и `src/features/clock/` (часы).

```
features/
├── dashboard/
│   ├── DashboardScreen.tsx     # корень экрана, сетка 12×6, размещение виджетов
│   ├── layout.ts               # (план) декларативная раскладка виджетов
│   ├── WidgetSlot.tsx          # (план) grid-позиция + анимация + WidgetBoundary
│   ├── useBurnInShift.ts       # (план) защита от выгорания
│   └── useNightMode.ts         # (план) ночное затемнение
└── clock/
    ├── ClockWidget.tsx         # карточка: циферблат слева, цифры и дата справа
    ├── AnalogClock.tsx         # SVG-циферблат + стрелки, анимация rAF + useRef (без ре-рендеров)
    ├── DigitalDate.tsx         # время ЧЧ:ММ, день недели, число и месяц; ре-рендер раз в минуту
    ├── clockMath.ts            # углы стрелок — чистая функция
    └── useClock.ts             # время, выровненное по границе секунды/минуты (используют и другие виджеты)
```

```
     │            ЧАСЫ                    │       ПОГОДА          │
 r2  │      14:37  (секунды мелко)        │   +12° ☁  УФ 3        │
     │      Вторник, 7 октября            │   почасовой прогноз   │
 r3  │                                    │                       │
     ├──────────────────┬─────────────────┼───────────────────────┤
 r4  │                  │                 │                       │
     │   ПРОБКИ         │   ПРОБКИ        │     ТЕЛЕМЕТРИЯ        │
 r5  │  Дом → Работа    │  Работа → Дом   │  CPU  RAM  T°  Uptime │
     │  32 мин  ▲ +8    │  25 мин  ●      │  ▁▂▃▅▂▁ графики       │
 r6  │                  │                 │                       │
     └──────────────────┴─────────────────┴───────────────────────┘
```

### 2.2. Декларативная конфигурация

```ts
// features/dashboard/layout.ts
export interface WidgetPlacement {
  id: 'clock' | 'weather' | 'traffic' | 'telemetry';
  col: number; colSpan: number;
  row: number; rowSpan: number;
  enterDelayMs: number;          // каскад анимации появления
}

export const DASHBOARD_LAYOUT: WidgetPlacement[] = [
  { id: 'clock',     col: 1, colSpan: 7, row: 1, rowSpan: 3, enterDelayMs: 0   },
  { id: 'weather',   col: 8, colSpan: 5, row: 1, rowSpan: 3, enterDelayMs: 80  },
  { id: 'traffic',   col: 1, colSpan: 7, row: 4, rowSpan: 3, enterDelayMs: 160 },
  { id: 'telemetry', col: 8, colSpan: 5, row: 4, rowSpan: 3, enterDelayMs: 240 },
];
```

- Позиции задаются через inline `style={{ gridColumn: `${col} / span ${colSpan}`, gridRow: … }}` — Tailwind не умеет динамические классы без safelist.
- Раскладка **валидируется unit-тестом**: ни один виджет не выходит за 12×6 и виджеты не пересекаются.
- Каждый виджет получает гарантированный размер ячейки и **обязан** уместить в неё контент без скролла (адаптируя количество строк/точек).

### 2.3. `WidgetSlot`

```tsx
<WidgetSlot placement={p}>          {/* grid-позиция + анимация входа */}
  <WidgetBoundary name={p.id}>      {/* изоляция ошибок */}
    <WeatherWidget />               {/* сам виджет из features/weather */}
  </WidgetBoundary>

```

## 3. Часы

Ячейка: колонки 1–7, строки 1–3 (~574×278 px). Карточка `ClockWidget` использует **тот же контейнер, что все виджеты**: `overflow-hidden rounded-card bg-surface-1 p-4`, без бордеров, градиентов и стекла — дашборд выглядит монолитно. Слева аналоговый циферблат 232 px, справа цифровое время и дата.

**Правило стиля:** циферблат и стрелки — плоские (flat), цвета только из дизайн-токенов (`fg-*`, `surface-*`, `status-*`), без бликов, теней и градиентов. Классы Tailwind `stroke-*`/`fill-*` применяются к SVG-элементам напрямую.

### 3.1. Отображение

| Элемент | Формат (`ru-RU`) | Стиль |
|---|---|---|
| Циферблат | Без цифр: кольцо-трек, 60 минутных делений, 12 часовых | Кольцо `stroke-surface-2` (как трек прогресс-баров), часовые деления `stroke-fg-muted`, минутные `stroke-fg-muted/40`; статичный SVG |
| Стрелки | Часовая (5 px) и минутная (3 px) — прямые линии со скруглёнными концами; секундная (1.2 px) с коротким хвостом и центральной точкой — единственный цветной акцент | `stroke-fg-primary`; секундная `stroke-status-bad` / `fill-status-bad`; плавный ход (sweeping hand) |
| Время | `21:30` (24-часовой, без секунд) | `text-[88px] font-extralight tracking-tight tabular-nums text-fg-primary` |
| Разделитель | Тонкая линия 40 px | `h-px bg-surface-2` (как разделитель в погоде) |
| День недели | `СРЕДА` | `text-label uppercase tracking-[0.3em] text-fg-secondary` |
| Дата | `7 октября` | `text-xl font-light text-fg-secondary` |

Секунды цифрами и мигающее двоеточие не показываются: секунды «живут» на секундной стрелке, а ежесекундный ре-рендер цифровой части не нужен.

Форматирование — через **заранее созданные** `Intl.DateTimeFormat` (создание форматтера дорогое, не делать это на каждый тик).

### 3.2. Правило 60 FPS: `requestAnimationFrame` + `useRef` вместо состояния React

**Проблема.** Плавная секундная стрелка должна менять угол **каждый кадр** (60 раз/с). Если хранить угол в `useState`, React будет 60 раз в секунду проходить reconciliation и коммит компонента — лишняя нагрузка на CPU Pi 24/7 и риск пропусков кадров у всего дашборда.

**Решение (`AnalogClock.tsx`):**

1. Компонент рендерится React'ом **один раз** (`memo`, без пропсов, меняющихся во времени, без состояния).
2. На каждую стрелку — `useRef<HTMLDivElement>`.
3. В `useEffect` запускается цикл `requestAnimationFrame`: на каждом кадре `new Date()` → `handAngles()` (`clockMath.ts`) → **прямая запись** `ref.current.style.transform = 'rotate(…deg)'`. React об этих изменениях не знает и не участвует.
4. Cleanup эффекта вызывает `cancelAnimationFrame` — нет утечки цикла при размонтировании (и при двойном монтировании StrictMode).
5. **Каждая стрелка — отдельный HTML-слой** (`div.absolute.inset-0.will-change-transform` со своим SVG), а не элемент внутри общего SVG. Поворот такого слоя выполняет композитор на GPU без перерисовки; поворот элемента внутри SVG вызвал бы repaint всего SVG каждый кадр. Статичный циферблат — отдельный SVG, рисуется один раз.
6. Углы непрерывные: секундная учитывает миллисекунды (0.1° за кадр при 60 Гц), минутная — секунды, часовая — минуты. Время берётся из `Date` на каждом кадре, поэтому стрелки не «уплывают» от реального времени (нет накопления ошибки, как при инкременте угла).
7. `prefers-reduced-motion: reduce` → секундная стрелка тикает дискретно раз в секунду.
8. Вкладка в фоне — браузер сам приостанавливает rAF.

Измерено в headless Chrome (1024×600): 61 кадр/с, шаг секундной стрелки 0.096–0.102° за кадр, текст цифрового времени за это время не меняется — то есть React-ре-рендеров нет.

> Это **осознанное исключение** из общего правила «не крутить бесконечный rAF» (`Feature_Widgets.md`, 3.5): для стрелочных часов непрерывное движение и есть содержимое. Цикл обязан трогать только `transform` (композиторное свойство) и только через ref; любые новые постоянно анимируемые элементы делаются так же.

### 3.3. Цифровая часть: `useClock('minute')`

`DigitalDate` показывает часы и минуты, поэтому обновляется **раз в минуту** через `useClock('minute')` (`setTimeout`, выровненный по границе минуты):

| Подход | Плюсы | Минусы | Решение |
|---|---|---|---|
| `requestAnimationFrame` + `setState` | Синхронизирован с кадром | 60 ре-рендеров/с ради изменения раз в минуту | ❌ |
| `setInterval(60_000)` | Просто | Дрейф: смена цифры может опоздать почти на минуту | ❌ |
| **`setTimeout` с выравниванием** | 1 вызов/мин, смена ровно на границе минуты, без дрейфа | Чуть больше кода | ✅ **Выбрано** |

Правила `useClock`:
- Время **не кладётся в глобальный стор** — иначе тик затронет всех подписчиков.
- `useClock('minute')` используют и другие виджеты, которым нужно «текущее время» (погода — выбор часов прогноза и устаревание).
- Смена даты в полночь обрабатывается автоматически: каждый тик создаёт новый `Date`.

### 3.4. Источник времени

- Время берётся из системных часов Raspberry Pi (синхронизируются через NTP / `systemd-timesyncd`).
- Pi 5 имеет RTC, но без батарейки время после холодного старта без сети может быть неверным. Если бэкенд в snapshot сообщает, что `|serverTime − clientTime| > 60 с`, — показываем маленький предупреждающий значок у часов.
- Часы — **единственный виджет, работающий без бэкенда**.

### 3.5. Взаимодействие

- Долгое нажатие (≥ 1.5 с) на часы → экран `settings` (см. `Core.md`, раздел 2).
- Обычный тап — без действия (защита от случайных касаний).

## 4. Анимации

### 4.1. Появление виджетов (initial mount)

Каскадное появление при старте приложения и после возврата на дашборд:

```
opacity: 0 → 1
transform: translateY(12px) scale(0.98) → translateY(0) scale(1)
duration: 400 ms, easing: ease-kiosk, delay: placement.enterDelayMs
```

```tsx
// WidgetSlot.tsx — CSS-вариант, без доп. библиотек
<div
  className="motion-safe:animate-widget-in opacity-0 [animation-fill-mode:forwards]"
  style={{ ...gridStyle, animationDelay: `${placement.enterDelayMs}ms` }}
>
```

```ts
// tailwind.config.js
keyframes: {
  'widget-in': {
    '0%':   { opacity: '0', transform: 'translateY(12px) scale(0.98)' },
    '100%': { opacity: '1', transform: 'translateY(0) scale(1)' },
  },
},
animation: { 'widget-in': 'widget-in 400ms cubic-bezier(0.2,0.8,0.2,1)' },
```

### 4.2. Обновление данных

- Смена значения (температура, время в пути): **crossfade** старого и нового значения (`opacity`, 200–300 мс) или вертикальный «перелист» цифр (`translateY` внутри `overflow-hidden`).
- Для существенных изменений (например, время в пути выросло > 20%) — короткая подсветка карточки: пульс `opacity` фонового слоя-подсветки, **не** `box-shadow`.
- Числа **не** «прокручиваются» счётчиком на каждом тике телеметрии — слишком дорого и отвлекает.

### 4.3. Состояния загрузки

- До прихода snapshot — `Skeleton` внутри карточки (размеры совпадают с финальным контентом, чтобы не было «прыжка» лэйаута).
- Snapshot пришёл → контент плавно сменяет скелетон (crossfade 200 мс).

### 4.4. Бюджет

- Одновременно анимируется не более ~4 слоёв.
- После завершения анимации `will-change` снимается (CSS-анимации с `forwards` этого не требуют).
- Проверка: Chrome DevTools → Performance → Frames на реальном Pi; ни одного кадра > 16.6 мс при появлении дашборда.

## 5. Работа в режиме 24/7

### 5.1. Защита от выгорания (burn-in)

- `useBurnInShift`: каждые **5 минут** весь контент дашборда сдвигается на случайные **0–4 px** по X/Y через `transform: translate()` (transition 2 с — незаметно для глаза).
- Запас под сдвиг учтён в паддингах корня (16 px).

### 5.2. Ночной режим

- `useNightMode`: в заданном интервале (по умолчанию 23:00–07:00, настраивается на бэкенде, приходит в `SettingsChanged`):
  - на корень добавляется класс `night`;
  - поверх экрана — чёрный слой с `opacity: 0.6` (дешевле, чем `filter: brightness`);
  - секунды скрываются, мигание двоеточия отключается;
  - телеметрия переходит в упрощённый вид.
- Аппаратная яркость подсветки (если поддерживается дисплеем) — управляется бэкендом, фронт только отображает состояние.
- Тап в ночном режиме — временно (60 с) убирает затемнение.

### 5.3. Возврат на главный экран

- С любого другого экрана — через 30 с бездействия (см. `Core.md`).

## 6. Состояния экрана

| Состояние | Что видно |
|---|---|
| Первый запуск, snapshot ещё не пришёл | Часы + скелетоны в карточках виджетов |
| Норма | Все виджеты с актуальными данными |
| Нет связи с бэкендом | Часы работают, виджеты с последними данными + `StaleOverlay`, иконка «нет связи» |
| Ошибка рендера одного виджета | Фолбэк-карточка только этого виджета, остальные работают |
| Ночь | Затемнённый экран, крупные часы, минимум деталей |

## 7. Тестирование

- `formatClock` — unit-тесты: полночь, смена месяца/года, DST, локаль `ru-RU` (падежи месяцев: «7 октября»).
- `useClock` — fake timers: проверка выравнивания по границе секунды и отсутствия дрейфа за 24 ч эмуляции.
- `layout.ts` — тест на непересечение и попадание в сетку 12×6.
- Visual check: скриншот-тест (Playwright) с вьюпортом 1024×600 для каждого состояния из раздела 6.
